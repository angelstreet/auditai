# 0024 - French + English across the web app (TASK-C)

- Status: Accepted
- Date: 2026-10-17
- Deciders: maintainers
- Related: [0023](0023-auditor-auth-and-session.md), [0004](0004-mobile-web-survey-stack.md), [0019](0019-public-routes-playwright.md), PRD "Product languages" + NFR

## Context

The PRD requires English and French at launch. `packages/i18n` only exported the locale list; every
page, form, server-action message and metadata title was hard-coded English, apart from the respondent
survey (`/s/...`), which already carried its own FR/EN strings keyed by the submission locale.

## Decision

### Mechanism: small in-house typed dictionary, cookie locale (no URL prefix)

- **Catalogs** live in `packages/i18n/src/messages/` (`en.ts`, `fr.ts`, `admin.en.ts`, `admin.fr.ts`).
  `en` is the source of truth for the key set; `fr` is typed `Messages` (same shape, every leaf a string),
  so a missing or extra key fails `tsc`. `createTranslator(locale)` returns `t(key, vars)`; `key` is a
  typed dotted path (`MessageKey`). Unknown keys fall back to English, then to the key itself.
- **Message format**: an ICU subset (`{name}` placeholders, `{n, plural, one {#…} other {#…}}`) implemented in
  `translate.ts` on top of `Intl.PluralRules`. No ICU runtime dependency.
- **Locale resolution** (`apps/web/src/lib/i18n.ts`): `auditai_locale` cookie → `Accept-Language`
  (`negotiateLocale`, q-values, primary subtag) → default **`fr`**. The default is French because the
  product is delivered first to French-speaking clients and existing engagements default to `fr`.
- **Switcher**: `LanguageSwitcher` in the header writes the cookie and calls `router.refresh()`.
  The survey welcome page keeps its per-submission language toggle (stored with the submission via
  `/api/locale`); it also writes the cookie so the page chrome follows.
- **`<html lang>`** is set from the resolved locale; `generateMetadata` localises titles/OpenGraph.
- Client components use `I18nProvider`/`useI18n()` (provider mounted in the root layout); server
  components and server actions use `getT()`.
- Formatting goes through `Intl` helpers (`formatDate`, `formatNumber`, `formatCurrency`), not string concat.
- **Server-action errors** are localised; raw exception text is no longer returned to the browser
  (logged server-side instead), which also removes a minor information leak.

### Tests

- `packages/i18n`: key parity (same keys in en/fr), no empty strings, identical placeholder sets,
  plural blocks present with `other`, quiz-item parity, negotiation, plural selection, Intl formatting.
- `apps/web/src/lib/i18nKeys.test.ts`: every literal `t('…')` key used in source exists in the catalog;
  template-literal prefixes resolve to catalog branches.
- Playwright: `public-routes.spec.ts` runs every public surface in `fr` and `en` across the 3-viewport matrix and
  asserts `<html lang>` and that no raw message key renders; `i18n.spec.ts` covers `Accept-Language`
  negotiation, fallback, and the switcher.

### French register

**Vouvoiement** for everything client-, employee- and sponsor-facing (survey, quiz, intake, privacy).
Admin/auditor screens are also written in vouvoiement/neutral imperative. "Tableau du portefeuille",
"mission" (engagement), "référent" (referent), "locataire" (tenant) are the fixed terms. Brand name
EvolAI and the mascot tiers (Tortue / Renard / Chouette) are consistent across screens.
The FR tagline "Comprendre. S'adapter. Évoluer." and the mascot names are **drafts for owner review**
(no branding guide is in the repo).

keyed by `code` / option `value`, so translation can never alter scores.

### Rebase note

Auditor auth (ADR 0023) landed first: `/login`, the auth error messages from `resolveActor` and the admin
surfaces behind it are translated too. Admin and board Playwright cases sign in as the seeded synthetic auditor.

## Alternatives considered

- **next-intl**: mature, but adds a dependency, middleware and `[locale]` route segment that would rewrite every
  signed invite URL (`/s/<token>`) and require route moves across ~20 pages. Rejected for now; the typed
  catalog keeps a clean migration path (keys are already namespaced).
- **URL prefix (`/fr/...`)**: better for SEO of public pages, but the app is invitation-only and tokens are
  signed over fixed paths. Revisit if public marketing pages move into the app.
- **Locale only from Accept-Language**: no way for a user to override it.

## Consequences

- Every page reads the cookie/headers, so previously static pages (`/about`, `/privacy`) render dynamically.
- Adding a string = add to `en.ts`, then `fr.ts` (tsc and tests enforce it).
- `packages/ui` mascots keep English default labels; callers pass localised `label`.

## Gaps / follow-ups

- **CSV exports** keep stable column keys (machine round-trip). Localised header labels are not implemented;
  add a `labels` option to `runExport` if analysts need them.
- **Static landing pages** in `landing/` (brand, m12, m14, m15) are not translated; follow-up (cheap path: duplicate
  with `lang="fr"` or a client-side toggle).
- Seeded synergy theme labels and AI-generated text stay in their generated language.
- Strings added by TASK-A (auth) and TASK-B (erasure) after this lands must be added to both catalogs.
- Owner to review all `draft-fr` content and the FR tagline.
